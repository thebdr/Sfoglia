# Sfoglia, working notes for agents

- Governed by IMPLICATION→MACHINE: the contract is `.zen/contract.md`, evidence logs are `.zen/evidence/<ID>.md`, screenshots go to `.zen/evidence/runs/` (git-ignored, overwritten per clause).
- UI stack is **gpui-kit 0.7.3** (`gpui_kit::*` re-exports GPUI). The gpui-kit and design-guide skills are vendored under `.claude/skills/`; read `references/coding-guides.md` before any state-ownership or public-API decision.
- Commands: `cargo run` (app), `cargo test` (unit + headless UI + checklist freshness; the workspace default members cover xtask), `cargo run -p xtask -- formats` (regenerate `FORMATS.md` after touching a format clause).
- `FORMATS.md` is generated. Never edit it by hand; change the clause and regenerate.
- Headless UI tests live in `tests/ui.rs` and need the `test-support` dev-dependency feature; the first `cargo test` after a `cargo build` recompiles the gpui stack once.
- Screenshots from the agent shell: `CopyFromScreen` returns black; use `PrintWindow(hwnd, 2)` on the process's `MainWindowHandle` (see `.zen/evidence/C-001.md`).
- Linux verification runs in the VMware VM `C:\_VMs\LMint\LinuxMint64.vmx` (Linux Mint 22.3, X11, llvmpipe Vulkan): start it with `vmrun -T ws start <vmx>`, address via `vmrun getGuestIPAddress <vmx>` about a minute after the start (the `-wait` form hung twice on 2026-10-17 and never returned), then `ssh -i ~/.ssh/sfoglia_vm hyper@<ip>`. The shared folder `C:\_VMs\_Shared` is `/mnt/hgfs/_Shared` in the guest. WSL is unusable on this machine (company policy denies the VM service logon).
- CI: `.github/workflows/ci.yml`, jobs `test-windows` and `test-linux`, on the public repo https://github.com/thebdr/Sfoglia.
- Linux verification in the VM: copy `scripts/linux-verify.sh` to the VM with scp, run it there over SSH (`bash linux-verify.sh`), then fetch `~/sfoglia-linux.png` and `~/sfoglia-linux.log`.
- The `tree-sitter-languages` feature of gpui-kit compiles every grammar; enabling it re-resolved the lockfile and `cc` had to come down to 1.2.x (`cargo update -p cc`), see `.zen/evidence/C-005.md`.
- Effects such as a dock close or a theme change land after the window update ends: in headless tests, leave `update_window`, call `cx.run_until_parked()`, then assert. The same holds for the kit's input events: a field's `PressEnter` and an editor's `Change` reach their subscribers only after the update, so a test that presses Enter in a search field or types into an editor leaves the block before asserting on what the event does (see `tests/data.rs`).
- Windows captures of the real window: `pwsh scripts/windows-capture.ps1 -Out <png> -Args <file> -Keep` launches the app and saves a PrintWindow capture; `-ProcessId <pid>` captures a running window. Chords and wheel scrolls in that window can come from the user or from the agent through the computer-use tools (`request_access` with the name `sfoglia.exe`, the plain name Sfoglia resolves to nothing, then `key`, `scroll`, `zoom`), since the agent shell itself cannot bring windows to the foreground. A kept window locks `target/debug/sfoglia.exe`: close it (taskkill) before any cargo build or test, or the relink fails with "Access is denied".
- The highlighting rules (C-006) live in `src/rules.rs` (pure) and `src/viewers/rules_panel.rs` (store + panel); headless tests give the workspace a temp rule path through `Workspace::with_rules_path`, never the real one under `%APPDATA%`.
- The kit's inputs bind ctrl-f, ctrl-g, ctrl-h and ctrl-o inside the "Input" context; app chords that must work from inside a field take ctrl-shift (see `workspace::init`).
- `UniformListScrollHandle::logical_scroll_top_index` always answers 0 for a `uniform_list` (it reads child bounds the list never records); derive the top row from `base_handle.offset()` and `last_item_size.contents` as `HexView::top_row` does. Pixels are f32: lists taller than ~1.6e7 px round their offsets, hence the row window in the hex view.
- Headless tests that create big temp files use one fixed name and remove it at the end; a panicking run leaves it, and leftovers once filled the disk.
- The drive C: runs close to full. Since the dev profile keeps line tables only (no debug info for dependencies, see Cargo.toml: MSVC LNK1140 otherwise), `target/` stays around 3 GB with every test binary built. When space runs out, delete `target/debug/incremental` and this crate's own artifacts in `target/debug/deps` (ui-*, hex-*, highlight-*, sfoglia-*, xtask-*) rather than the dependency rlibs; critics must build in the repo target, never a scratch one. A running Linux VM adds an 8 GB `.vmem` to its folder on C:, so host test builds and the VM never run together: stop it (`vmrun -T ws stop <vmx> soft`) first.
- The dock never closes the last tab of its only group (`TabGroup::is_closable` needs somewhere to go); a headless close test must open a second file first. `Panel::closable` (base trait) gates `ClosePanel`: a modified text tab returns false.
- Editing (C-008): `text::encode` writes back in the file's encoding and endings; `TextView` owns the dirty flag, the save targets and a one-second disk stamp check; tests advance the clock with `cx.background_executor.advance_clock`.
- Each headless test binary links a ~500 MB debug database; with under 10 GB free, `cargo build --tests -j 1` before `cargo test` keeps link.exe from failing (LNK1180/LNK1201). Critics that add a probe test binary must delete its `zz_*` artifacts from `target/debug/deps` afterwards; prefer a probe inside an existing test file.
- Images (C-009): `src/images.rs` decodes through the image crate with GPUI's own feature set, SVG through resvg at exact size (GPUI's renderer applies a hidden smoothing factor), fonts through `text_system().add_fonts`; a family with a viewer is routed before the "text content opens as text" rule.
- Structured data (C-010): `src/data.rs` parses JSON (a serde seed straight into the arena, `arbitrary_precision` for the numbers' own digits), JSON Lines, XML (roxmltree with DTDs allowed, prefixed names), YAML (the `saphyr` document tree: typed keys, streams), TOML and INI into one pre-order arena (`Node { depth, end, key, kind, value }`); `src/viewers/data_view.rs` shows it as a `uniform_list` with its own rows focus (`DataTree` context for the arrows, Enter and Space, so the search field keeps its keys) and builds the raw `TextView` on first need. The kit's `TreeState` clones every visible child item on each expand, so it is not used.
- Markdown (C-011): the rendering is the kit's rich text (`gpui_kit::base::text::TextView` element over a `TextViewState`, the component facade lacks `image_source`); `src/markdown.rs` parses the same source with the `markdown` crate into an outline (blocks, headings, slugs) that the status row, the toggle (block index ↔ line) and `#fragment` links use, and sorts link and image addresses; `src/viewers/markdown_view.rs` builds the raw `TextView` at open and follows its `operations`/`reloads` as the data view does. The rich text parses on a background task: headless tests `run_until_parked` after opening and after each toggle. A link to a file reaches the workspace through the data-carrying `OpenLinkedFile` action (`#[action(namespace = sfoglia, no_json)]`).
- Closing the window (C-012): `Workspace::with_rules_path` registers GPUI's `on_window_should_close`; the kit's alert dialog comes from `WindowExt::open_alert_dialog` and is found headlessly under the id `dialog`; a test drives the request with `VisualTestContext::simulate_close` (the handler's answer, the window kept) and sees a removed window as `cx.windows()` empty. The test support's `label()` is the `aria_label` alone, never visible text; only the active tab is laid out, so typing into another tab means activating it first (`open_paths`). The kit's dialog slides in over 250 ms of real time: a headless test sleeps 300 ms and renders a frame before reading or clicking inside a freshly opened dialog, or the click lands where the button no longer is (the edit tests' `settle_dialog`).
- One workspace per headless test: a second `open_workspace` in the same `TestAppContext` runs the kit's and the app's init twice, and a pressed Enter then reaches its input twice (the tsv and utf16 sheet tests were split for this).
- Spreadsheets (C-013): `src/sheet.rs` parses delimited text with the `csv` crate (each record's byte span kept so a cell edit re-writes that record alone) and workbooks with `calamine` (`open_workbook_auto`; merged regions only through `Xlsx::merge_cells_by_sheet_name`; dates converted from serials by hand, no chrono); `src/viewers/sheet_view.rs` sits on the kit's `TableState<D: TableDelegate>`: a header click cycles the kit's own `ColumnSort` as Default → Descending → Ascending (a first click sorts descending), `dump()` reads cells through the delegate's `cell_text` (implement it or the dump is empty), header cells have the id `("col-header", col)`, and `TableEvent::SelectCell(row, col)` gives display rows. The xlsx fixture comes from `cargo run -p xtask -- fixtures` (rust_xlsxwriter); `book.xls` was saved by Excel through the desktop-control tools.
- PDF (C-014): SumatraPDF 3.6 embeds through `SumatraPDF.exe -plugin <hwnd> <file>` (its frame `SUMATRA_PDF_FRAME` becomes a child of the given window, sized once: `src/pdf_host.rs` moves it on every paint from a `canvas` in the view and hides it through the dock's `set_active` hook and the hex toggle); commands go to that instance by `WM_COPYDATA` with `dwData = 0x44646557` ("DdeW") and the DDE text in UTF-16, never by DDE (every instance registers the same `SUMATRA` service). GPUI's `Window::window_handle` shadows the `raw_window_handle` trait method: call `raw_window_handle::HasWindowHandle::window_handle(window)` in full. A headless test window has no native handle: the host is not started there (`HostState::NoWindow`). The kit's dock (0.7.3) never calls a panel's `set_active`: the workspace tells every panel on each render whether the dock shows it (`visible_panels`, `FilePanel::set_shown_by_dock`), which is how a hosted window hides behind another tab. The desktop-control tools' screenshot hides windows of apps outside its allowlist (SumatraPDF's among them) and the user declined that grant, so frame visibility is read with `FindWindowExW`/`IsWindowVisible` (the scratch `frames.ps1` pattern), never from a screenshot.
- Tools outside Sfoglia (`src/tools.rs`): tests pin tools through `ToolSet::stubbed` and `Workspace::with_tools`, never through the `SFOGLIA_*` variables (process-global); the stand-ins live in `tests/stubs/` (`.cmd` on Windows, `.sh` elsewhere, kept executable in git), and a version banner must be digits and dots alone (`mutool version 9.9`). The real SumatraPDF is found on the dev machine, so a test that wants it absent must pin it to `None`.
- Chords need a drawn focus: GPUI dispatches an action along the path to the focused element in the last rendered frame, so a focus left on a tab that went behind (opening a text tab moves none) or on nothing (after the closing dialog) makes every chord dead; `Workspace::render` moves such a focus to the active tab. `Window::dispatch_action` is deferred and reads the focus of the rendered frame, so focusing a handle and dispatching in the same handler does not reach it; close a tab through `DockArea::remove_panel` instead (the kit's `ClosePanel` handler sits on the tab group the focus is in).
- Desktop-control coordinates on this machine: the tools' frame is 1389×868 for the 1920×1200 screen (physical = frame × 1.383); with the app at its default place the tab bar is near frame y 72 and the status row near y 633. A click meant for the status row that lands in the panel hits the hosted SumatraPDF frame instead. `GetGUIThreadInfo(0)` (the scratch `frames.ps1` pattern with `GetCursorPos`) tells which window holds the keyboard and where the last click landed. SumatraPDF makes its own frame the foreground window as it starts: a foreground check must accept a window rooted in Sfoglia's.
- Archives (C-015): `src/archive.rs` is pure (containers and codecs by name and signature, listing, one entry's bytes, extraction through `safe_join`, the `7z l -slt` parser); `src/viewers/archive_view.rs` sits on the kit's `TableState` with `row_selectable`. The kit's table focus handle is dead for key dispatch inside a dock panel (with it focused, `available_actions` lists only the dock's and the workspace's listeners), so the view owns a `rows_focus` on the wrapper of the table (`ArchiveRows` context: Enter, the arrows, Home, End) and re-focuses it on every `SelectRow`; `Focusable::focus_handle` hands it to the dock. The kit's `InputState::set_value` fires no `Change`: a test that filters types into the field (`ctrl-a`, then `input`). An opened entry is a `FileInfo` with an `origin` (`EntryOrigin`: archive, path inside, an `Arc<TempFolder>` removed on drop under `<temp>/sfoglia/entry-<pid>-<n>`), its viewers told `set_read_only(reason)` (the text view's save then says why; the data, sheet and Markdown views forward it to the text view they build). The real 7-Zip prompts on the console for a password it is not given: every command passes `-p` (empty allowed), `-sccUTF-8` for the names, and a null stdin. `tests/fixtures/bundle.rar` was made once with WinRAR's `Rar.exe` (not on CI); the headless rar test uses `tests/stubs/sevenzip.{cmd,sh}` on `fake.rar` (the stand-in exits 7 without `-sccUTF-8`, wants `-psfoglia` for a `*secret*` archive, writes the named entries alone on `x`). An `Entry` carries `raw`, its index inside the container (`None` for a folder `fill_in_folders` adds because the archive records none); `list` with a password checks it on the smallest encrypted entry (`verify_password`), and a read of an encrypted 7z entry maps any decoder failure to `WrongPassword`. Once-made fixtures (random salts or the real 7-Zip): `secret.7z`, `entries.7z`, `secret.zip` and `legacy.zip` are written by xtask when absent; `lzma.zip`, `bcj.7z` and `bundle.rar` were made by hand with the real 7-Zip and WinRAR.
