## C-002: Format support checklist generated from the contract
- **Date:** 2026-10-14
- **Source:** ingest (user-request-2026-10-13#checklist)
- **Description:** `FORMATS.md` is the user-facing checklist of every extension Sfoglia knows: one row per format family listing its extensions, Read status, Write status, the clause that proves it, and who requested it and when. It is generated by one command, `cargo run -p xtask -- formats`, from the clauses of this contract whose description begins with an extension list, so it can never claim more than a verified clause does: a pending clause renders as planned, an unverified clause as in progress, a verified clause as done. The Requested column names the origin from the clause's provenance (the part before the hash of an ingest tag, or the bare source) and a date: a real calendar date found inside the origin, else the clause's own date; a family with no origin or no real date is an error. ## C-004: Open a file and route it to the right viewer
- **Date:** 2026-10-14
- **Source:** ingest (user-request-2026-10-13#core)
- **Description:** A file reaches Sfoglia from the command line (every argument is a path to open), from the Open dialog (Ctrl+O, several files at once), or by dropping it onto the window. Each file is identified first by its extension, looked up in the extension table generated from this contract's family clauses, and then by its content: a definitive signature at the start of the file (PNG, JPEG, GIF, WebP, Photoshop, OpenEXR, PDF, 7z, xz, bzip2, RAR, tar, TNEF, MP3, FLAC, WAV, AVI, MPEG program stream, and an ISO media file whose brand names its family) overrides a misleading extension; a container signature shared by several families (ZIP, OLE compound, TIFF, gzip, Ogg, Matroska, ISO media of unknown brand) never overrides a known extension and only settles an unknown one; an extension listed by several families is settled by a signature naming one of them and otherwise by contract order; a file with no known extension and no signature is text when its bytes decode as text (UTF-8, UTF-16 by its mark, or single-byte text when they carry no byte-order mark, are not UTF-8, and hold no control byte beyond whitespace and escape nor DEL; bytes 0x80 to 0x9F are Windows code-page punctuation and count as text) and binary otherwise; a byte-order mark promises its encoding, so bytes behind one that do not decode are binary; a character, unit or surrogate pair cut off by the end of the sampled bytes is forgiven; and plain text, in any of these encodings, that merely begins with the bytes of a signature is still text; the one signature believed inside text is a PDF's full header line (`%PDF-` with a version and a line ending), because a whole PDF can be printable. Until a family's viewer exists, its tab shows the file's name, path, size, detected family and the clause that will bring the viewer; a path that cannot be read still opens a tab, which states the error. Each open file is a tab in the centre of a dockable layout, several at once; opening a file that is already open activates its tab instead of adding one, and a file whose tab was closed is no longer open, so opening it again adds a fresh tab. The extension table and the checklist come from the same clauses, so the application and `FORMATS.md` cannot disagree, and a stale table fails `cargo test`.
