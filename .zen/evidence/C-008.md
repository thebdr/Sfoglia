# C-008 — Edit and save text-based files — lab notebook

The clause states intent; this file holds the research/spike log, sweeps, and design notes that would otherwise bloat the clause (clause altitude, C-012).

## 2026-10-16: design
- The kit's editor already brings typing, cut, copy, paste, undo, redo (ctrl-z, ctrl-y) and a search-and-replace
  panel (Search on ctrl-f, Replace on ctrl-h, `open_search`, `set_search_query`, `replace_all_search_matches`);
  the editor is simply no longer read-only (`Editor::readonly(!editable)`), read-only staying for a file with
  undecodable UTF-16 units, whose text could not be written back faithfully.
- `text::encode(text, encoding, ending)`: the byte-order mark the encoding carries, then the text with every
  break (CRLF, LF, lone CR) as the chosen ending; Latin-1 and Windows-1252 map characters back (the Windows-1252
  table in reverse for 0x80..0x9F, so the five undefined bytes round-trip too) and refuse the first character
  they cannot hold with its line. Mixed and no endings write LF. Round-trips are asserted for every fixture.
- The view (`TextView`) keeps the path, the encoding and ending the next save writes, a dirty flag set by the
  editor's `InputEvent::Change`, the last message, and a `DiskStamp` (modified time and length) of the file as
  last read or written. A one-second timer task compares the stamp and raises the changed-on-disk bar; Reload
  re-reads (`set_value`, which emits no change event), Keep mine refreshes the stamp. The status-row encoding and
  endings items are clickable and cycle; a changed choice marks the tab modified so Ctrl+S writes it.
- Dirty marker: `FilePanel` observes the view, emits `PanelEvent::LayoutChanged` and notifies, so the dock
  re-reads `tab_name` (the name plus " •") and `closable` (false while modified; the tab group refuses the close).
- Kit behaviour found in the headless test: the dock never closes the last tab of its only group (the group has
  nowhere to go), so the close test opens a second file first. In C-004's test several tabs were open, which is
  why closing worked there.
- The C-005 clause and test changed in one place each: the editor is no longer "read-only", and the mixed-endings
  fixture's status item now reads "mixed, saves as LF"; typing into it changes the buffer, and the fixture on
  disk is asserted untouched.

## 2026-10-16: critic passes
- First pass (commit f374ef3): refuted, three findings. (1) After saving a mixed-endings file the status item still
  read "LF (was mixed)": the "read with" value was re-detected from the editor buffer, which still held the mix.
  Fix: the item takes what was written (LF, the chosen ending, or none for a file without breaks); a headless test
  saves the mixed fixture, asserts the LF bytes and the label "LF", then chooses CRLF and asserts both again.
  (2) "A file with undecodable units is read-only" was pinned by no test (the behaviour was right). Fix: a
  UTF-16 file with a lone surrogate: not editable on the view and the editor, typing and replace-all change
  nothing, the status-row choices do not move, Ctrl+S refuses with its message and the bytes and modification
  time stay. (3) Keep mine on a tab without edits left "saved" and the next Ctrl+S did nothing, so the outside
  change silently won. Fix: Keep mine counts as a modification (the text now differs from the file) and the
  clause says so; pinned with a clean tab, an outside write, Keep mine, Ctrl+S and the file holding the buffer.
- Outside the clause, noted by the critic: closing the window with modified tabs has no guard. Parked as a
  pending delta rather than widened into this clause.
- Second Linux pass at 5ab22bb: build and suite green (six editing tests), the three captures refreshed with the
  same content.
- Second pass (commit 5ab22bb): refuted, one finding, confirmed by a probe: when Reload or Revert could not read
  the file (deleted by another program), `reload` still cleared the modified flag while the edited text stayed on
  screen, so the tab looked saved, could be closed, and Ctrl+S did nothing: the edits were silently losable.
  Fix: a failed read keeps the text, says why, and marks the tab modified; the next save writes the text back
  and recreates the file. The clause states it; the headless test deletes the file, goes through Reload and
  then Revert, and asserts the message, the marker, the refusal to close and the recreated file.
