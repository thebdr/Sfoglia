# C-006 — Custom highlighting rules with regex and priority — lab notebook

The clause states intent; this file holds the research/spike log, sweeps, and design notes that would otherwise bloat the clause (clause altitude, C-012).

## 2026-10-15: design
- Mechanism: gpui-base's text decorations. `EditorState::create_decorations_collection` gives a
  `TextDecorationCollection`; `set(Vec<TextDecoration{range, HighlightStyle}>)` replaces its contents and the
  editor composes them over the syntax styles (`compose_decorations`: a decoration wins every property it sets;
  the first collection has precedence). Decorations track edits, which P-004 will need.
- Ownership: `RulesStore` (an entity) holds the file's text, its parse (`rules::RuleFile`) and the path; it is
  the only writer of the file. `TextView` observes it and recomputes its spans on notify; `RulesPanel` holds an
  editable `EditorState` whose `InputEvent::Change` pushes the text into the store. The store never pushes text
  back into the panel's editor, so there is no feedback loop.
- Overlap resolution (`rules::resolve`): candidates sorted by priority desc, start asc, length desc, declaration
  order; a BTreeMap of occupied ranges; each candidate keeps the pieces nothing above it took. O(n log n + overlaps).
- Parsing: `toml::Spanned` on sets and on each rule table gives the header line of a bad rule; rule fields are
  typed per rule (`Table::try_into`) so one bad rule never sinks the others; unknown fields are reported and
  ignored. The regex crate's multi-line error is collapsed to one line for the panel.
- Globs: `globset`, case-insensitive, matched against the file name alone. A single glob may be a string.
- Config path: `dirs::config_dir()/sfoglia/highlight-rules.toml`. A missing file shows the commented example
  (`rules::STARTER`) and is written on the first change. Tests use a temp path per test, never the real one.
- Effects: the editor's change event, the store's notify and the views' re-paint are all delivered when the
  update that typed ends (the same rule as the dock close in C-004); the test leaves `update_window`, parks,
  and asserts in the next frame.
- Test gotcha: typing through `window.input` goes character by character as keystrokes, so lines are typed
  without spaces and newlines come from `window.press("enter")`; the kit's bracket and quote auto-pairing
  produced exactly the typed text. A Bash heredoc on this machine turns a doubled backslash into one.

## 2026-10-15: critic passes
- First pass (commit c33fc78): refuted, five findings. (1) `^` and `$` did not see CRLF line ends and `.` took in
  the `\r`: the editor keeps `\r\n`, the only fixture is LF, no test used CRLF. Fix: the regex is built with CRLF
  mode; exact ranges asserted on CRLF and LF text in the unit test and on a CRLF file in a headless window.
  (2) Unknown fields at the top level and in a set were dropped silently (a typo such as `flies` left a set with no
  globs); only rule fields were checked. Fix: both levels are reported on the field's own line and ignored; the
  rule-level report now names the field's line too. (3) A rule `name` of the wrong type loaded as "rule N" without
  a report. Fix: the name is typed like every other field. (4) The missing-file start and the first write were
  untested, and a file that exists but cannot be read (not UTF-8) would have been overwritten by the first
  keystroke. Fix: such a file is never written; the panel says so; two headless tests pin the starter, the first
  write (directory included) and the unreadable file staying byte for byte. (5) "The name alone" was not
  discriminated by the UI test's globs. Fix: a file in a directory whose name matches a glob, and a `plc_*.txt`
  file whose path would not match from its start, are asserted.
