# C-015: Archives read: the entries listed, opened inside Sfoglia and extracted

## Stack (2026-10-18)

The crates named in `.zen/remaining.md` for P-021, all from the registry, no C code: `zip` 9 (no default
features; deflate, bzip2, zstd, lzma, time), `tar` 0.4, `flate2` (already in), `bzip2` 0.6, `lzma-rs` 0.3 (pure
Rust xz and lzma, one-shot), `zstd` 0.14, `sevenz-rust2` 0.24 (`aes256`). rar, cab, iso, rpm, deb, cpio, lha,
lzh, arj, chm, xar, wim, dmg, vhd, hfs, dd, deskthemepack and Unix `compress` go through an installed 7-Zip,
found by `src/tools.rs` as C-014 finds its tools (`Tool::SevenZip`: `SFOGLIA_7ZIP`, `Program Files\7-Zip\7z.exe`,
then `7z.exe`, `7zz`, `7z`, `7za` on the search path; the version from the `.exe` resource or the banner).

## Design

- `src/archive.rs` (pure): `Container { Zip, Tar(Option<Codec>), SevenZ, Lone(Codec), External }` and
  `Codec { Gzip, Bzip2, Xz, Lzma, Zstd, Compress }` are separate kinds; `container_of(name, head)` reads the
  bytes first (`7z\xbc\xaf\x27\x1c`, `Rar!\x1a\x07`, `PK\x03\x04`, `ustar` at 257, the codec magics) and the
  name after (`tgz`, `tbz2`, `txz`, `tzst`, `tlz`, `taz`, `tar.z`, `x.tar.<codec>`, the lone suffixes, the external
  list); `decode(codec, reader)` is the one codec path a tar and a lone file both go through, so a codec of the
  user's own plugs in there (P-030 names it). `list` gives `Listing { container, entries, encrypted }` with
  `Entry { name, size, packed, modified, method, crc, is_dir }` (folders as entries of their own, `/`-terminated);
  `read_entry` one entry's bytes; `extract` writes all or chosen entries under `safe_join` (no absolute path, no
  drive, no `..`: skipped and named in `Extracted::skipped`); `materialize` writes one entry into a `TempFolder`
  (`<temp>/sfoglia/entry-<pid>-<n>`, removed on drop) for a tab; `parse_seven_zip_listing` reads `7z l -slt`
  (`Path`, `Size`, `Packed Size`, `Modified` cut to the minute, `Folder = +` or `Attributes = D`, `CRC`, `Method`);
  `Listing::describe` makes the status text (`ZIP, 12 entries, 1.2 MB packed from 4.5 MB`; a tar has no packed
  sizes, so the file size stands in). Errors: `NeedsPassword`, `WrongPassword`, `NoTool`, `Bad(reason)`.
- 7-Zip commands: `l -slt -y -sccUTF-8 -p<pw> <file>`, `e -so -y -sccUTF-8 -p<pw> <file> <entry>`,
  `x -o<dir> -y -sccUTF-8 -p<pw> <file> <entries>`, stdin null. Read on the real 7-Zip 26.04 the same day:
  without `-p` and with no console, an encrypted archive makes it print `Enter password (will not be echoed):`
  and die with `Break signaled` (exit 255); `-p` alone is the empty password and it answers `Cannot open encrypted
  archive. Wrong password?` instead; names print in the OEM code page unless `-sccUTF-8` (`naïve.txt` came back
  as `na�ve.txt` without it); `Modified` carries seven decimals (`2026-10-18 14:00:00.0000000`, local time).
- `src/viewers/archive_view.rs`: the kit's `TableState<ArchiveDelegate>` (`row_selectable`, `sortable`,
  `col_resizable`) with Name, Size, Packed, Modified, Method, CRC; a header click cycles the kit's `ColumnSort`
  (descending first); the search field filters on `Change` (a substring of the name, any case); Enter, a double
  click or the arrows work on the rows; `Extract all` / `Extract selected` prompt for a folder
  (`prompt_for_paths` with `directories: true`); the password field and `Unlock` show for an encrypted archive
  (locked headers or encrypted entries), each wrong password counted in the status row; a container that needs
  7-Zip with none found shows the install hint, `Look again` (`ToolSet::refresh`) and the bytes (the hex view)
  under it. An entry opens through the data-carrying action `OpenArchiveEntry { archive, index }` dispatched
  after the update (as C-011's links): the workspace finds the view by its path, asks it to `materialize` the
  entry, and opens the file with a `FileInfo` whose `origin` names the archive, the path inside and the
  `Arc<TempFolder>`; the tab is `archive › inside`; a second Enter on the same entry selects that tab.
- Read-only: the panel tells the viewer `set_read_only(reason)` (`read-only: an entry of bundle.zip; extract it
  to edit a copy`); the text view turns its editor read-only and its save returns the reason; the data, sheet and
  Markdown views forward it to the text view they build (the sheet's cell edit and the data view's edits already
  refuse on a read-only text view).
- Fixtures from `cargo run -p xtask -- fixtures`: `bundle.zip` (deflate, a folder entry, bzip2, stored, zstd;
  one UTF-8 name), `bundle.tar` and the same through gzip, bzip2, xz, zstd and as `tgz`, `bundle.7z` (LZMA2),
  `secret.7z` (AES, password `sfoglia`, written once and kept: the salt is random), `note.txt.{gz,bz2,xz,lzma,zst}`,
  `escape.zip` and `climb.tar` with a `../` entry (the tar crate refuses `..` in `set_path`, so the name goes into
  the header bytes by hand), `fake.rar` (the signature and zeros), all at 2026-10-18 12:00 UTC; `bundle.rar` made
  once with WinRAR's `Rar.exe` (RAR5, `-m3`) for the manual pass through the real 7-Zip. The 7-Zip stand-in
  `tests/stubs/sevenzip.{cmd,sh}` answers the banner (`24.08`), a canned `-slt` listing of two files and a folder,
  the readme's bytes on `e -so`, and writes both files on `x`.

## Findings on the way

- The kit's table focus handle is dead for key dispatch inside a dock panel: with the table focused,
  `Window::available_actions` listed the dock's and the workspace's listeners only (not the table's own
  `SelectDown` and not the view's), and `bindings_for_action(OpenEntry)` was empty, so Enter went nowhere. The
  view now owns `rows_focus`, tracked on the wrapper of the table (`ArchiveRows` context: Enter, up, down, Home,
  End), hands it to the dock through `Focusable::focus_handle`, moves the selection itself through
  `set_selected_row` and `scroll_to_row`, and re-focuses the wrapper on every `SelectRow` so a click on a row
  keeps the keyboard there. The data view's `DataTree` focus (C-010) is the same pattern.
- `InputState::set_value` fires no `Change`: the filter test types (`ctrl-a`, then the text). The kit's input has
  no password mode in 0.7.3 (`masked` is a crate-private field): the password shows as typed.
- The tar crate rejects `..` in a path it sets itself (`paths in archives must not have ..`); the fixture writes
  the name into the header bytes and `append`s the prepared header.
- A tar through xz from `lzma_rs::xz_compress` is larger than the tar (the crate's encoder stores): fine for a
  fixture, read back by the same crate.

## Refuter passes

- First pass (commit bad0a73, then e60c99b and 42206f9): refuted on eight gaps, all with a mutation run or a
  probe on archives made with the real 7-Zip. Fixed and pinned: (1) a 7z with encrypted entries and clear
  headers (7-Zip's default) listed with a wrong password and read with a wrong one said `UnexpectedEof`: the
  listing now checks a given password on the smallest encrypted entry (`verify_password`, zip and 7z) and a
  read of an encrypted 7z entry maps any decoder failure to `WrongPassword`, `NeedsPassword` with none; the
  viewer re-lists without the wrong password where the headers allow it and counts the refusal (`entries.7z`,
  written once with `set_encrypt_header(false)`). (2) Encrypted zips were untested and AES ones unreadable:
  `aes-crypto` on, `secret.zip` (AES-256) and `legacy.zip` (ZipCrypto) written once; the unit test
  `encrypted_entries_check_the_password_in_zips_and_clear_header_seven_zips` pins list, read, extract and the
  Unlock check for all three. (3) A spreadsheet entry was never checked read-only: Ctrl+S said nothing with no
  raw text built, and a cell edit was refused with the undecodable-units reason; the sheet and data views
  gained `refuse_save` (the reason in their status row) and give their own reason on an edit, the workspace's
  Ctrl+S routes an entry tab to `FilePanel::refuse_save`; the entry test clicks a cell, edits it and reads the
  reason, the file untouched. (4) Packed sizes were computed from the code under test: the tests now state
  them (zip 38/160/67/22, `ZIP, 5 entries, 287 B packed from 258 B`; 7z 40/139/71/17, `7Z, 5 entries, 267 B
  packed from 258 B`; secret 32). (5) The 7-Zip stand-in ignored `-p`, `-scc` and the entry names: it now exits 7
  without `-sccUTF-8`, refuses every password but `-psfoglia` for an archive named `*secret*` with 7-Zip's own
  `Cannot open encrypted archive. Wrong password?`, writes the named entries alone on `x` (everything when none
