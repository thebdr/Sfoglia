# C-013: Spreadsheets and delimited tables

## Design (2026-10-18)

- `src/sheet.rs` (pure): a delimited text parses through the `csv` crate (RFC 4180, `flexible` for ragged
  records, no header handling of its own) into a `Grid` of string fields with each record's byte span, so a cell
  edit re-writes that record alone; `detect_delimiter` counts comma, semicolon, tab and pipe outside quotes over
  the first twenty lines and keeps the candidate that splits them into the most fields the same way (a `.tsv`
  is tabs regardless); `format_record` writes a record back quoted only where needed. An Excel workbook reads
  through `calamine` (`open_workbook_auto`: xls, xlsx, xlsm, xlsb, the templates) into sheets of typed `Cell`s:
  `Data::Int`/`Float` as their own digits (`format_number`: fifteen significant digits, the shortest exact form
  preferred), `DateTime` through our own serial-to-civil conversion (no chrono: the 1900 system's phantom
  1900-02-29 kept at serial 60, the 1904 epoch honoured for xlsx), booleans `TRUE`/`FALSE`, errors as calamine
  prints them, a formula as the cached value `worksheet_range` gives; merged regions from
  `merge_cells_by_sheet_name` for the xlsx family (calamine exposes none for xls). Column widths and number
  formats are not exposed by calamine: columns are sized to their content and the workbook's own widths and
  formats are parked as P-029.
- `src/viewers/sheet_view.rs`: the kit's `TableState<SheetDelegate>` (virtual rows, resizable columns,
  sortable headers, cell selection, a row-number column) over the current sheet's cells with a display order the
  sort permutes; `perform_sort` follows the kit's own cycle on a header click (Default → Descending →
  Ascending → Default, so a first click sorts descending, as the kit draws it); `compare_cells` puts numbers
  before text, text case-insensitively, and the delegate keeps empty cells last in either direction. The
  search field (`sheet-search`) finds the next cell containing the text in display order from the selected
  cell on; the edit field (`sheet-edit`) holds the selected cell and Enter writes it back into the raw text
  through the text viewer (`replace_all` + `note_edit`, as the data view's pretty-print does), the grid
  re-parsed; Ctrl+Shift+D toggles the raw text as the data view does; the Reload / Keep mine bar shows on the
  grid side; a workbook has a sheet bar and is read-only.
- Fixtures: `tests/fixtures/table.csv` (quoted commas, an embedded line break, doubled quotes, an empty field, a
  ragged last record), `table.tsv` (the same by tabs), `utf16.csv` (UTF-16 LE with a mark), `book.xlsx`
  generated by `cargo run -p xtask -- fixtures` (the `rust_xlsxwriter` crate: dates with formats, a datetime,
  booleans, a formula with its cached result, a merged range, a column width, three sheets one of them empty)
  and `book.xls` saved from it by Excel as a 97-2003 workbook through the desktop-control tools.

## Implementation notes

- Kit findings: the table's `dump()` reads cells through the delegate's `cell_text`, which the trait defaults to
  an empty string (implemented); the header cell's click selects the column and the sort lives on the header's
  arrow (`("icon-sort", col)`), so the clause and the hint speak of the arrow; the kit cycles Default →
  Descending → Ascending; `InputState::set_value` wants the window, so the cell selection flows from the
  table's `SelectCell` event through `subscribe_in`.
- The `csv` crate keeps a trailing empty field itself (a first draft added a second one); its record
  positions can sit on the line break that ended the record before, so each record's span starts after any
  break and runs to the next record's start with the break taken off.
- The Write tool strips a trailing tab from a line, so `table.tsv` is written with `printf` to keep the last
  record's trailing empty field.
- `rust_xlsxwriter` writes formulas without a result unless `Formula::set_result` is given; Excel saved the
  same book as `book.xls` with every value, the merged region among them (calamine reads merges for xlsx only).

## Refuter passes

- First pass (commit 0746214): refuted. (1) High: a cell edit in a CRLF file corrupted it. The grid was parsed
  from the decoded text with its carriage returns while the edit was applied to the line-feed text, so the
  record spans were off by the `\r` count: the first edit after opening merged records (and Ctrl+S saved the
  damage) or fell off a boundary and did nothing in silence. Fixed: the file is parsed from the line-feed text
  as every re-parse already was (the cells carry no `\r` either), and a span that no longer fits says so in the
  status row; a headless test opens a CRLF copy, edits D2 then B3, checks the exact text and the CRLF bytes
  Ctrl+S writes. (2) A 1904-epoch legacy xls read its dates four years early: the flag is now read from
  `Xls::has_1904_epoch` too, and `book1904.xls` (saved by Excel with the 1904 system through the desktop-control
  tools) is read in the fixture test. (3) The delimiter went by the first line alone, so a title line in front
  of semicolon data fell back to commas: the count most lines share decides now, with unit cases for a title
  line and for decimal commas. (4) `format_number` cut small fractions to fifteen decimal places, not fifteen
  significant digits: it now keeps the shortest exact form up to fifteen significant digits and otherwise
  rewrites the fifteen-digit scientific form in full. (5) A time-only cell in a 1904 workbook showed a date:
  a serial below one is a time of day in either system now, and the clause says so. Held: the edit while
  sorted (display row to data row to record), the search after a sort or a toggle, `cell_name` with the
  header off, a ragged edit, the read-only text, chart sheets, the workbook's bar paths.
- Second pass (commit 4d3f4ae): refuted. (1) High: a two-line cell lost its break in the one-line edit field
  (the kit's single-line input strips line breaks from a set value) and Enter wrote the damaged value back.
  Fixed: the field shows a break as ⏎ and writes it back as a break, and a value left as it was writes nothing
  (`C2 unchanged`, the tab unmarked); the edit test now starts on C2. (2) A time just short of midnight showed
  `24:00:00`: the serial is rounded to whole seconds before the split, so it carries into the next day (a time
  alone wraps to `00:00:00`). (3) An ISO date stored as text in an xlsx kept its `T`: shown as a space.
  (4) The 64 MB budget was measured on the file's bytes at open and on the decoded text after a toggle: the
  decoded text everywhere now, and the clause says so. Noted and stated: an edit or the header toggle shows
  the file's order again, and a sort drops the cell selection (the view's own copy of the selection is gone,
  the table's is the one truth, so no stale cell is named after a sort). Held: the edit field after a toggle,
  the header record, quoting edge cases, a ragged edit, a second edit's spans, the UTF-8 mark, one-line and
