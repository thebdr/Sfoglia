# C-012: Closing the window asks about modified tabs

## Design (2026-10-17)

- The platform's close request (the title bar's close button, Alt+F4, the window manager on Linux) reaches
  GPUI's `on_window_should_close` handler, registered in `Workspace::with_rules_path` with a weak handle to the
  workspace. The handler answers `true` when no tab is dirty; otherwise it records the modified tabs in tab order
  (`Closing { queue, message }`), opens the kit's alert dialog through `WindowExt::open_alert_dialog`, and answers
  `false`. A second request while the dialog shows changes nothing.
- The dialog is rebuilt from the closing state at every frame (the kit calls the builder on each render): the
  title `Save changes to “name”?`, the file's folder beneath it, `N more file(s) have unsaved changes` while more
  follow, and the text viewer's message after a refused save, in the danger colour. Its footer: `Cancel`,
  `Discard all` and `Save all` (only while more follow), `Discard changes` (danger), `Save` (primary). The labels
  follow the design guide's table for unsaved changes (`Discard changes`, not `Yes`); the title names the object
  and the decision, the body carries only what changes it (where the file is, how many follow, why a save failed).
- A decision applies at once through the text viewer's own operations: `Save` is C-008's save (the file's encoding
  and endings), `Discard changes` is C-008's Revert (`reload`), so the file is untouched. `Save all` and
  `Discard all` settle the queue in order; a refused save stops with its message on that tab. When the queue is
  empty the dialog closes and `window.remove_window()` closes the window without a second question. Escape closes
  the dialog as Cancel: the dialog's `on_close` drops the closing state.
- Quitting: on Windows and Linux Sfoglia quits by closing its only window, so the one hook covers both; GPUI's
  `on_app_quit` cannot veto and is not used.

## Implementation notes

- `src/workspace.rs`: `Closing`, `Decision`, `may_close`, `closing_facts`, `open_closing_dialog`,
  `closing_dialog_closed`, `decide`, `settle`; the hook in `with_rules_path`; the `closing` field.
- Headless tests in `tests/edit.rs`: `closing_the_window_asks_about_every_modified_tab_before_it_closes`,
  `save_all_writes_every_modified_tab_and_closes_the_window`,
  `discard_all_restores_every_modified_tab_and_closes_the_window`,
  `a_refused_save_keeps_the_window_open_with_its_message`. They drive the close request with GPUI's
  `VisualTestContext::simulate_close` (which calls the handler and reports its answer without removing the
  window) and read the dialog through its ids (`dialog`, `close-title`, `close-folder`, `close-more`,
  `close-message`, `close-save`, `close-discard`, `close-cancel`, `close-save-all`, `close-discard-all`); a
  removed window shows as `cx.windows()` empty after the update.
- Kit findings: only the active tab is laid out, so a headless test that types into another tab brings it up
  first (`open_paths` activates an open tab); the test support's `label()` is the accessibility label alone
  (`aria_label`), never the visible text, so every div a test reads carries one; a dialog opened through the
  window extension is found under the id `dialog` in the window's layers.
