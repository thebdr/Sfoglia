# C-012: Closing the window asks about modified tabs

## Design (2026-10-17)

- The platform's close request (the title bar's close button, Alt+F4, the window manager on Linux) reaches
  GPUI's `on_window_should_close` handler, registered in `Workspace::with_rules_path` with a weak handle to the
  workspace. The handler answers `true` when no tab is dirty; otherwise it records the modified tabs in tab order
  (`Closing { queue, message }`), opens the kit's alert dialog through `WindowExt::open_alert_dialog`, and answers
  `false`. A second request while the dialog shows changes nothing.
- The dialog is rebuilt from the closing state at every frame (the kit calls the builder on each render): the
  title `Save changes to “name”?`, the file's folder beneath it, `N more file(s) have unsaved changes` while more
  follow, and the text viewer's message after a refused save, in the danger colour. Its footer: `Cancel`,
  `Discard all` and `Save all` (only while more follow), `Discard changes` (danger), `Save` (primary). The labels
  follow the design guide's table for unsaved changes (`Discard changes`, not `Yes`); the title names the object
  and the decision, the body carries only what changes it (where the file is, how many follow, why a save failed).
- A decision applies at once through the text viewer's own operations: `Save` is C-008's save (the file's encoding
  and endings), `Discard changes` is C-008's Revert (`reload`), so the file is untouched. `Save all` and
  `Discard all` settle the queue in order; a refused save stops with its message on that tab. When the queue is
  empty the dialog closes and `window.remove_window()` closes the window without a second question. Escape closes
  the dialog as Cancel: the dialog's `on_close` drops the closing state.
- Quitting: on Windows and Linux Sfoglia quits by closing its only window, so the one hook covers both; GPUI's
  `on_app_quit` cannot veto and is not used.

## Implementation notes

- `src/workspace.rs`: `Closing`, `Decision`, `may_close`, `closing_facts`, `open_closing_dialog`,
  `closing_dialog_closed`, `decide`, `settle`; the hook in `with_rules_path`; the `closing` field.
- Headless tests in `tests/edit.rs`: `closing_the_window_asks_about_every_modified_tab_before_it_closes`,
  `save_all_writes_every_modified_tab_and_closes_the_window`,
  `discard_all_restores_every_modified_tab_and_closes_the_window`,
  `a_refused_save_keeps_the_window_open_with_its_message`. They drive the close request with GPUI's
  `VisualTestContext::simulate_close` (which calls the handler and reports its answer without removing the
  window) and read the dialog through its ids (`dialog`, `close-title`, `close-folder`, `close-more`,
  `close-message`, `close-save`, `close-discard`, `close-cancel`, `close-save-all`, `close-discard-all`); a
  removed window shows as `cx.windows()` empty after the update.
- Kit findings: only the active tab is laid out, so a headless test that types into another tab brings it up
  first (`open_paths` activates an open tab); the test support's `label()` is the accessibility label alone
  (`aria_label`), never the visible text, so every div a test reads carries one; a dialog opened through the
  window extension is found under the id `dialog` in the window's layers.

## Refuter passes

- First pass (commit 2936ddb): refuted. (1) The queue followed the order the files were opened in, not the tabs
  as they stand: a tab dragged to the front was asked about last. Fixed: `panels_in_tab_order` walks the centre
  layout (group by group, left to right) and the question follows it; a test moves a tab through the dock's
  `move_panel` and asserts the question names it first while the opening order stays. (2) `Save all` stopping
  at a refused save had no assertion: a test with hello.txt, latin1.txt (`€`) and utf16le.txt pins the tab before
  saved, the dialog on the refused tab with its message and the count of what is left, the tab after untouched.
  (3) Escape as Cancel had no assertion: a test presses it and asks again. (4) A restore that could not read the
  file back (the file deleted meanwhile) still advanced the queue and could close the window with the edit
  unrestored: now it stays on the tab with the viewer's `cannot read` message, as a refused save does, and the
  clause says so; a test deletes the file and presses Discard changes. Noted from the probe: Enter fired the
  kit's Confirm and closed the dialog with no decision; Enter is now `Save` (the primary button) and the clause
  says so. Held: `is_dirty` and `editable_text` agree for text, data, Markdown and hex-shown tabs; a clean tab
  is skipped; a second request changes nothing; Cancel's path; the plural; focus after Cancel; no other quit path.
- Second pass (commit 7810337): refuted. (1) A file opened by a relative path (`sfoglia hello.txt` from its
  folder) showed an empty folder line: the folder is now taken from the absolute path, and a test opens
  `tests/fixtures/hello.txt` relative to the crate root and checks the crate root's absolute folder. (2) Enter as
  Save had no assertion: a test presses it on a refused tab (the dialog stays with the message, twice) and on the
  last tab (the exact bytes written, the window gone). (3) The walk across tab groups had no assertion: the
  tab-order test now also splits a third tab off to the left and expects it first with `2 more files`. (4) A gap
  in the clause: a tab whose save and restore both fail (the file's folder gone) could only be killed, every
  request re-asking. Now the refused restore's message says a second `Discard changes` drops the edit, and it
  does; the test deletes the file, discards twice over two requests, and sees the window go. Held: the closing
  state after any dialog path, a queued tab changing meanwhile, a dirty data tab's text, the chosen encoding,
  the Reload/Keep-mine bar case, a second request, the recomputed queue after Cancel.
- Third pass (commit 218fcc0): refuted. (1) The second `Discard changes` only took the tab off the queue: its
  text view stayed modified, so with another tab after it a `Cancel` left the edit in place and the next request
  asked again. Now the drop closes the tab (the dock's `remove_panel`): its file is gone and its edit with it;
  a test with two tabs sees the dialog move on, the dropped tab closed after `Cancel`, and the next request ask
  about the other alone. (2) `Discard all` at a refused restore was unspecified: the clause now says it stops
  there as `Save all` does and a second `Discard all` drops the edit and goes on; a test covers it. (3) On
  Linux `std::path::absolute` keeps `..`: the folder now comes from `canonicalize` (the `\?\` prefix taken
  off on Windows) with `absolute` as the fallback for a file gone meanwhile, and the relative-path test opens
  `tests/../tests/fixtures/hello.txt`. Held: the marker after Cancel, a file turned directory or unreadable, a
  refused save then a refused restore, the split-group count, the rules panel, the Reload/Keep-mine bar,
  `on_ok` after `remove_window`, the stamp after a save, the tests' entrance wait (a slow entrance fails a
  test, never passes one falsely).
- Fourth pass (commit a051b91): refuted on one point. Once the file was gone, the folder line fell back to the
  path as spelled (the temp folder's 8.3 form on Windows, `..` kept on Linux). Now the folder itself is
  canonicalised and the name joined, `absolute` the last fallback; the refused-restore test asserts the folder
  after the delete. Held, by a probe: the dock's `remove_panel` takes a tab with no closability check, so a
  dropped tab is really gone, an emptied split group is normalised away, the active index clamped and no welcome
  screen shows while another tab remains; a later open of the same path makes a fresh tab; no event re-enters
  `settle`; UNC, long and re-cased paths come out right; the marker resets per request; no vacuous assertion.
