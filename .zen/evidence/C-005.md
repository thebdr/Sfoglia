# C-005 evidence: source and text viewing with syntax highlighting

## 2026-10-14: design, from the gpui-kit study
- The viewer is the kit's code editor: `EditorState::new(window, cx).language(name).line_number(true).soft_wrap(false)
  .default_value(text)` rendered through `Editor::new(&state).readonly(true)`. It virtualizes rendering and highlights
  with tree-sitter; the `tree-sitter-languages` feature compiles every grammar the kit ships (35 names mapped in
  `src/text.rs`, each checked against `Language::from_str`).
- Decoding is Sfoglia's own (`src/text.rs`): UTF-16 by byte-order mark (lossy, counting undecodable units), UTF-8 with
  the mark stripped, otherwise Latin-1 byte-per-character. Line endings are counted exactly (CRLF, LF, CR, mixed, none);
  the line count is one more than the number of breaks, zero for an empty text.
- Any readable file whose content is text, or that is routed to the text family, opens in the text viewer until its own
  family has a viewer (C-004's info rows remain for binary families and unreadable paths).
- Theme: `Theme::change(mode, Some(window), cx)` on the `ToggleTheme` action, bound to Ctrl+Shift+T.
- Enabling the grammar feature re-resolved the lockfile: `cc` had to come down to 1.2.x for `tree-sitter-sequel`
  (`cargo update -p cc`).

## 2026-10-14: exact highlighting, recorded from the real engine
- The kit's Rust query styles `fn`/`let` as keyword, `main` as function, `u32` as type, `42` as constant (not number,
  which the JSON query uses for `17`), `println` and `!` as function.macro, the string literal as string; unstyled gaps
  tile the rest, and the spans tile the whole text. JSON keys are property, `true` boolean. In the default light theme
  several names share a colour (constant and boolean; property and variable), so the test resolves each expected span
  through `theme.style(name)` and asserts the exact style sequence.
- Plain text and an unknown language emit no spans; the dark theme styles keywords differently from the light one.

## 2026-10-14: 300 000 lines
- A generated 300 001-line file (18 MB): open plus first frame 1.68 s in a debug build on the Windows machine (decode,
  rope build, tree-sitter-free since `text` has no grammar, first layout); a steady frame 32 ms. The test asserts a
  steady frame under 250 ms, a bound chosen for slow CI runners; the smoothness claim rests on the measured 32 ms and
  on the manual scroll in the real window.
