## 2026-10-14: why CI, and the workflow
- WSL Debian exists on the development machine but cannot start from the agent session or from the app's own terminal
  panel: `Wsl/Service/CreateInstance/CreateVm/HCS/0x80070569` ("the user has not been granted the requested logon type").
  Root cause (Security log, event 4625): `vmcompute.exe` requests a type-5 (service) logon for the VM's virtual account
  (`NT VIRTUAL MACHINE\<guid>`) and gets 0xC000015B. The exported user-rights policy shows `SeServiceLogonRight` set to an
  explicit list of domain SIDs plus `NT SERVICE\ALL SERVICES`, without `NT VIRTUAL MACHINE\Virtual Machines` (S-1-5-83-0),
  which Windows grants by default. The machine is domain-joined (CSIT), so a group policy most likely overrides the right.
  Fix is a security-policy change for the user or IT, not for the agent. Until then CI is the only Linux proof.
- `.github/workflows/ci.yml`: two jobs, `test-windows` (windows-latest) and `test-linux` (ubuntu-latest, with the system
  libraries gpui needs: ALSA, fontconfig, OpenSSL, zstd, Wayland, X11-xcb, xkbcommon, Vulkan, clang, cmake). Each job
  runs `cargo build --locked`, `cargo test --locked` and the checklist freshness check. Triggered on pushes to main and
  on pull requests.
