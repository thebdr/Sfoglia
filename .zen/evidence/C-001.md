# C-001 evidence: app shell on gpui-kit

## 2026-10-13: stack decision
- GUI: gpui (Zed's framework), chosen by the user over egui and iced. The published `gpui` crate on crates.io is 0.2.2
  (2025-10-22) and stale. The maintained path is **gpui-kit 0.7.3** (longbridge/gpui-kit, released 2026-10-12), which pins
  `gpui-pre =0.3.9` snapshots of Zed's crates and re-exports GPUI plus 75+ components: code editor with tree-sitter
  highlighting, dock layout, data tables, markdown and HTML rendering, AccessKit, headless UI integration tests, and an
  experimental wry-based `gpui-webview` (Windows WebView2; Linux X11 only, no Wayland).
- Windows toolchain present: rustc 1.96.1 (msvc), Visual Studio 2022 and 18 Community, Windows SDK 10.0.26100, CMake 4.3.
- cargo could not reach crates.io: schannel `CRYPT_E_NO_REVOCATION_CHECK`, because this network blocks CRL and OCSP lookups.
  Fixed with `[http] check-revoke = false` in `~/.cargo/config.toml`.
- Linux: WSL Debian exists on this machine but cannot be started from the agent session (HCS logon-type error 0x80070569).
  Linux verification goes through CI (P-024) or the user's own terminal.

- Launched `target/debug/sfoglia.exe`. `Get-Process sfoglia` reported one process (pid 21772) with `MainWindowTitle = "Sfoglia"`,
  window class `Zed::Window`, window rect 1552 x 1134 device pixels (1200 x 800 logical at 125 % scaling plus frame).
- Capture: `PrintWindow(hwnd, PW_RENDERFULLCONTENT)` into `.zen/evidence/runs/C-001-after.png` (overwritten per run, git-ignored).
  Read back: a light window with the native title bar reading "Sfoglia" and the word "Sfoglia" centred in the body. Nothing else drawn.
  (`CopyFromScreen` from the agent shell produced an all-black frame; PrintWindow is the capture path that works from this session.)

  not reachable through the OS accessibility tree in this build. The in-process check is the headless test `tests/ui.rs`
  (`shell_window_shows_the_application_name`), which queries gpui-kit's own observed element tree for the label.
- Lockfile: enabling `test-support` on the dev-dependency pulled the weak `gpui-fast?` dependency into the lock, which conflicts
  with the pinned gpui-pre crates on `cocoa` and `unicode-properties`. `cargo generate-lockfile` resolved it (cocoa 0.26.0,
  unicode-properties 0.1.3, plus the gpui-fast 0.1.8 crates present in the lock but not built).
- Linux: not verified in this session; see P-024.

## 2026-10-14: automated check and refuter finding
- `tests/ui.rs` opens the shell headlessly through gpui-kit test support and queries the observed element tree;
  `src/shell.rs` unit tests pin the title and size in `window_options()`. `cargo test`: 12 tests across the workspace (2 + 1 + 9), exit 0
  (recorded in runs/C-001.json).
- **Refuter (fresh context): refuted.** The headless test compared the element's accessibility label with `APP_NAME`,
  but that label came from `.aria_label(APP_NAME)`, set independently of the rendered child text. Mutation
  `.child("WRONG")` still passed. gpui-kit's pinned GPUI exposes no enumeration of anonymous rendered text, so the
  fix makes the label a function of the rendered text instead of a parallel constant (see the second pass below).

## 2026-10-14: second pass
- First fix: a `title()` helper builds the label and the child from one `SharedString`. **Refuter (second pass): refuted
  again**, correctly: equality by construction is not an assertion; `.child("WRONG")` and `.child("Sfoglia — a viewer")`
  inside the helper still passed the 30–200 px width bound and the 2 px centring check.
- Second fix (a `wrong_assumption` about what the observation layer can see, fixed in the test): the test now shapes
  `APP_NAME` with the window's text system in the style the gpui-kit root applies (theme font family, window rem size)
  and requires the observed element to be exactly that wide (±1 px) and one line high; a string of another width changes the
  width. Centring stays at ±2 px.
- Final build launched again: pid 15292, `MainWindowTitle = "Sfoglia"`, window rect 1216 x 839 (this session's display
  runs at 100 % scaling, the earlier one at 125 %). `PrintWindow` capture overwritten at `runs/C-001-after.png`; read
  back: title bar "Sfoglia", the word "Sfoglia" centred in an otherwise empty light body. Process stopped afterwards.
- Mutation proof of the shaping assertion: rendering "WRONG" instead of the name failed the test (element width 48px vs
  shaped 67.2px); rendering an empty string failed at the visibility assertion. shell.rs restored byte-identical, suite green.
- Third refuter pass: a same-width variant such as "sfoglia" (68px vs 67.2px shaped) stays inside the one-pixel tolerance, so the
  automated leg cannot tell it apart; the clause now says so and leaves such variants to the manual capture. Known blind spot.
- Fourth refuter pass: holds. Verdict recorded; clause marked verified.
