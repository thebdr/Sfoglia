## 2026-10-14: refuter findings (zen-refuter, fresh context) and their routing
1. **bug** — any clause whose description *mentioned* `Extensions:` in prose became a family: C-002's own description
   produced a junk row (`\`, cargo, so, an, a, and, later, or`) and the header counted 17 families. The staleness test
   locked the wrong output in. Fix: a family is a clause whose description *starts with* `Extensions:`; every token must
   be extension-shaped (`[a-z0-9][a-z0-9.-]*`) or the generator errors; fixture clause C-009 covers the prose mention;
   a real-contract test asserts the family set equals exactly the clauses that start with `Extensions:`.
2. **bug** — a bare `cargo test` at the root ran only the root package (workspace with a root package and no
   `default-members`), so the staleness check never fired. Fix: `default-members = [".", "xtask"]`. Proven by making
   the contract stale on purpose and watching the bare `cargo test` exit non-zero, then restoring (log below).
3. **wrong_assumption** — the Write flag read "txt now; docx is a later extension" as `later`. Rule made explicit in the
   clause: only the part before a semicolon decides; `out of scope` → no, a deferral-only sentence → later, otherwise
   mirrors Read. P-007 and P-010 now render `planned`. Fixture C-007 asserts the present grant wins.
- Edges the refuter confirmed hold: dotted tokens (`tar.gz`), lists without a closing `. `, CRLF input, `###` headings.
